## 배경

용어집 탭의 동적 용어집 주입 체크박스를 켜고 번역을 시작해도 주입이 꺼진 채 실행됐다. 화면은 체크 상태인데 config.json에는 False가 남아 있었다.

## 문제

1. 설정 파일을 쓰는 주체가 둘이었다. 설정 탭은 서비스 설정의 복사본에 자기 위젯 값만 덮어 저장했고, 용어집 탭은 파일 찾기·추출·편집 같은 동작의 부수 효과로만 저장했다. 체크박스 자체에는 저장 시그널이 없었다.
2. 번역 시작 시 설정 탭 저장이 아직 저장되지 않은 용어집 탭 값을 복사본의 옛 값으로 덮어썼다. 실제 위젯으로 체크 후 번역 시작 저장을 호출해 False가 저장되는 것을 재현했다.
3. 설정 탭에 있던 "설정 저장"은 설정 탭 값만, "설정 불러오기"는 설정 탭 화면만 다뤘다. 저장 실패도 예외를 삼켜 "저장 성공"을 띄웠다.

## 결정과 근거

- 각 탭은 위젯 값을 설정에 써 넣는 일과 설정으로 화면을 채우는 일만 맡고, 파일 저장은 조정자 한 곳에서 한다. 메인 창이 조정자를 만들어 두 탭에 연결하므로 어느 경로로 저장해도 모든 탭 값이 함께 저장된다.
- 버린 접근: 위젯 값이 바뀔 때마다 서비스의 메모리 설정을 곧바로 고치는 방식. 변경은 작지만 설정을 쓰는 곳이 위젯마다 흩어져 같은 종류의 누락이 다시 생기기 쉽다.
- 탭을 단독으로 만들 때(테스트 등)는 자기만 등록된 조정자를 쓰게 해 기존 탭 단위 동작을 유지했다.
- 번역 시작처럼 작업 흐름 중의 저장은 실패해도 작업을 막지 않고 경고 로그만 남긴다. 사용자가 누른 "설정 저장"은 실패를 오류창으로 알린다.
- 설정 저장·불러오기는 모든 탭이 대상이므로 상태 표시줄로, 번역 시작·취소는 어느 탭에서든 누를 수 있게 탭 영역 아래로 옮겼다. 버튼의 동작과 상태는 계속 설정 탭이 관리하고 메인 창은 배치만 맡는다.
- 진행률 막대와 상태 문구는 사용자의 결정으로 설정 탭에 남겼다.

## 검증

- 신규 테스트 5개: 용어집 탭 값이 설정 탭 저장을 거쳐도 유지됨, 반대 방향, 불러오기가 두 탭을 모두 갱신함, 저장 실패 보고, 메인 창 버튼 배치와 저장 동작. 전체 스위트가 통과했다.
- 실제 설정으로 메인 창을 화면 없는 모드로 띄워 캡처해 버튼 위치를 확인했다. 글꼴이 들어간 실제 창과 클릭 동작은 확인하지 않았다.

## 미해결

- 다른 탭에서 번역을 시작하면 진행 상황이 보이지 않는다(진행률 표시가 설정 탭 안에 있음).
- 설정 탭의 CLI 실행 경로 칸은 여전히 세 CLI 프로바이더가 공유해, 지정한 전체 경로가 다른 CLI로 넘어갈 수 있다.
