## 배경

2026-10-25 Cursor 프로바이더로 용어집 추출을 돌린 로그에서 세 가지가 보였다. 응답을 문자열로 받아 JSON을 복구하고 있었고, 검열 차단이 일반 오류로 올라왔고, 취소할 때 `maximum recursion depth exceeded`가 났다. CLI별 구조화 출력 옵션을 비교하다가, 호출 인자가 클라이언트까지 전달되는지도 확인했다.

## 문제

- 도메인 서비스는 GeminiClient 시그니처로 호출한다. 지침은 `system_instruction_text`, 스키마는 `generation_config_dict["response_schema"]`로 넘긴다. Claude, Codex, AGY, Cursor 클라이언트는 `system_instruction`과 `response_schema`만 받아서 이 값들이 `**kwargs`로 버려졌다. 그래서 CLI 프로바이더에서는 프리필 시스템 프롬프트, PDF 줄바꿈 지시, 번역 기억 블록이 빠졌다. Claude, Codex, Cursor는 스키마도 받지 못했다. AGY만 스키마를 따로 읽고 있었다. 수정 전 Claude 실호출에서는 스키마 3종 모두 JSON이 아닌 응답이 왔다.
- Claude `--json-schema`와 Codex `--output-schema`는 최상위 array를 400으로 거부한다. 앱 스키마 3종(용어집, 인물 메모, 무결성 번역)은 모두 `list[...]`다. Codex는 strict 모드라서 모든 객체에 `additionalProperties: false`와 전체 required도 요구한다.
- 앞 항목의 Cursor 결정 중 "`TemporaryDirectory(ignore_cleanup_errors=True)`로 정리 실패를 막는다"는 틀렸다. Python 3.10의 `_rmtree` onerror는 PermissionError가 나면 이 플래그와 무관하게 자신을 다시 부른다. 프로세스가 아직 폴더를 잡고 있으면 무한 재귀가 되어 CancelledError를 가렸다. 프로세스 종료도 폴더 정리보다 늦게 실행되고 있었다.
- Cursor는 콘텐츠 차단도 `ActionRequiredError: Request blocked … usage guidelines`로 보낸다. 앞 항목에서는 ActionRequiredError를 모두 요금제 문제로 분류해서, 검열 분할 경로를 타지 못했다.

## 결정과 근거

- `base_client.resolve_call_options`가 두 이름 체계를 모두 읽고, CLI 클라이언트 4개가 같은 헬퍼를 쓴다. Ollama와 OpenAI 호환 클라이언트가 이미 같은 방식으로 `kwargs`를 읽고 있었다. 도메인 서비스의 호출 이름을 바꾸는 방법은 Gemini 경로까지 건드리게 되어 택하지 않았다.
- 배열 스키마는 `{"items": [...]}`로 감싸고 `$defs`를 최상위로 올린다. 응답에서 다시 꺼내 JSON 문자열로 돌려준다. 문자열로 돌려주는 이유는 호출부가 이미 문자열 파싱 경로를 갖고 있고, 수정 전 Claude와 Codex도 문자열을 반환했기 때문이다.
- Codex에만 strict 변환을 적용한다. 모든 객체에 `additionalProperties: false`, 전체 속성 required, `default` 제거다. 기본값이 있던 선택 필드도 모델이 채워 보내게 된다.
- Cursor는 `mkdtemp` 뒤 `finally`에서 프로세스를 먼저 끝내고, 그다음 `shutil.rmtree(ignore_errors=True)`로 지운다. `ignore_errors=True`는 onerror를 부르지 않아서 3.10의 재귀를 피한다. 프로세스 종료를 `finally` 한 곳으로 모았다.
- Cursor의 "Request blocked"와 "usage guidelines" 문구는 검열 예외로 분류한다. 요금제 외 모델의 ActionRequiredError는 여전히 일반 오류다.

## 검증

- 2026-10-25 전체 테스트를 실행했다. 582 passed, 7 skipped. 신규 `test_cli_call_options.py` 11건 중 클라이언트 테스트 8건은 수정 전 코드에서 모두 실패했다. 임시 worktree에서 확인했다.
- 실호출에서 스키마 3종(무결성, 용어집, 인물 메모)을 `generation_config_dict`로, 지침을 `system_instruction_text`로 넘겼다. Claude(haiku), Codex(gpt-6-luna), Cursor(grok-4.7-low), AGY(default) 모두 배열을 반환했다. 지침 속 표식 `[[SYS-OK]]`가 번역문에 붙어 지침 전달을 확인했다.
- Cursor 실호출을 3초 뒤 취소하자 CancelledError가 그대로 올라왔고 `btg_cursor_*` 임시 폴더가 남지 않았다.

## 미해결

- Codex의 사용자 기본 모델(gpt-6-astra)과 앱 기본값 gpt-5.5는 현재 무료 계정에서 400을 낸다. 앱 기본 모델값은 바꾸지 않았다.
- Cursor는 여전히 스키마를 강제할 수 없어 프롬프트 지시에 의존한다. 모델이 글로 거절하면("I can't help…") 오류가 아닌 정상 응답으로 오므로 검열로 분류하지 않는다.
- Codex와 AGY가 권한 확인을 건너뛰는 문제(프롬프트 인젝션 위험)와 AGY effort `xhigh` 반영은 이번 범위에 넣지 않았다.
- 앱 실제 화면으로 프리필 지침이 번역 결과에 반영되는지는 확인하지 않았다. 클라이언트 단위의 표식 실험으로만 확인했다.
