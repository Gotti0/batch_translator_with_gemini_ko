## 배경

무결성 분할 작업(PR #14~#16)을 하는 동안 테스트를 돌릴 때마다 수집 단계에서 멈추거나 실패가
섞여 나와, 내 변경이 무언가를 깨뜨렸는지 판단하려면 매번 `git stash`로 기준선을 다시 재야 했다.
그 과정에서 두 번 오진했다. 기존 테스트의 목 이름 오류를 내 회귀로 착각했고, asyncio 이벤트 루프
오염을 Qt 인스턴스 공유로 잘못 지목했다. 사용자와 인터뷰로 범위를 정하고 정리에 들어갔다.

## 문제

전체를 처음 재보니 `95 failed / 171 passed / 6 errors`였다. 처음 사용자에게 보고한 "남은 것 4건"은
크게 축소된 수치였다. 실패의 성격이 제각각이라 한 가지 처방으로 풀리지 않았다.

- 사라진 `gui` 패키지(Tkinter 시절)를 검증하는 테스트 64건
- 구현이 없는 배치 기능 테스트 19건과 수집 실패 3건. 네 쌍이 평면 경로와 계층 경로에 중복
- `asyncio.run()`이 남긴 이벤트 루프 오염으로 뒤에 오는 테스트가 죽는 것 3건
- 수동 스크립트 두 개가 주석 처리 중단으로 `IndentationError`
- 이름이 바뀐 API를 부르는 테스트들
- 실제 Gemini API를 호출해 무료 티어 쿼터를 쓰는 테스트

## 결정과 근거

- **이벤트 루프 정리를 가장 먼저 넣었다.** 오염이 남아 있으면 이후 단계에서 무엇이 진짜 실패인지
  계속 헷갈린다. 이번 작업에서 두 번 오진한 원인이 그것이었다. `conftest.py`가 아예 없어 테스트 간
  전역 상태를 정리할 자리가 없었다.
- **삭제와 수정을 같은 PR에 섞지 않았다.** 삭제는 판단이 단순하고 양이 많으며(2477줄), 수정은
  판단이 필요하고 양이 적다. 섞으면 리뷰어가 대량 삭제에 묻혀 수정 쪽을 보지 못한다.
- **구현이 없는 기능의 테스트는 사양서가 아니라 부채로 봤다.** 배치와 Tkinter GUI 모두 대상 모듈이
  저장소에 없고 앱 코드 어디에서도 참조하지 않는다. 고쳐 쓸 대상이 없으므로 지우고 Git 이력에 맡긴다.
  대안으로 수집에서만 제외하는 방법이 있었으나 죽은 코드가 계속 남는다.
- **수동 스크립트 둘은 검증 대상이 달라 다르게 처리했다.** `test_resume_verification`은 이어하기라는
  실사용 경로를 검증하므로 그대로 살려 pytest 테스트로 옮겼다. `test_failure_scenario`는 검증하려던
  동작(빈 결과가 완료로 기록되지 않음)이 현재 구현에 없어서 검증 지점을 아래층으로 옮겼다. 메인 번역
  루프는 반환값을 보지 않고 성공으로 기록하며, 빈 결과를 막는 실제 방어선은 `translate_text_async`다.
- **실제 API 테스트는 명시적 opt-in으로 바꿨다.** 기존에도 키가 없으면 건너뛰었지만 `test/.env`에
  키를 둔 개발 환경에서는 매번 실제 API를 불러 하루 한도를 갉아먹었고, 한도가 차 있으면 스위트가
  붉게 나왔다. `RUN_GEMINI_API_TESTS=1`일 때만 돌게 했다. 목으로 바꾸는 방안은 버렸다. 실제 응답의
  thinking 동작을 보는 것이 목적이라 목으로 만들면 검증 가치가 사라진다.
- **파이프라인 통합 테스트를 tmp_path로 격리했다.** 저장소 루트에 `sample_input.txt`를 만들고 지우지
  않아, 남은 메타데이터 때문에 두 번째 실행부터 이어하기로 들어가 출력 파일을 만들지 않았다. 자기가
  남긴 부산물로 자기가 실패하는 비멱등 테스트였다. EPUB 쪽은 없는 생성 스크립트를 부르고 있어서,
  파이프라인이 mimetype과 .xhtml 항목만 본다는 점을 확인하고 테스트 안에서 최소 EPUB을 만들었다.

## 검증

- `pytest test/` 3회 연속 `184 passed / 7 skipped`, 수집 오류 0. 파일을 골라 돌리든 전부 돌리든,
  순서를 뒤집어도 결과가 같다.
- 저장소에 부산물이 남지 않는 것을 `git status`로 확인했다.
- 실행 시간이 약 18초에서 9초로 줄었다. 실제 API 호출이 빠진 몫이다.
- 삭제 대상은 지우기 전에 근거를 확인했다. 배치 모듈 네 개와 `gui` 패키지가 저장소에 없고 앱 코드
  어디에서도 참조하지 않는다.

## 미해결

- **메인 번역 루프에 빈 결과 검사가 없다.** 정상 경로에서는 아래층이 빈 응답을 예외로 바꾸므로
  도달하기 어렵지만, 그 성질이 깨지면 빈 번역문이 조용히 완료로 기록된다. 테스트 정리 범위를
  넘어서는 동작 변경이라 손대지 않았다.
- 건너뛰는 7건 중 6건은 실제 API 테스트고 1건은 제거 예정인 동기 메서드 테스트다. 후자는 해당
  메서드가 실제로 사라질 때 함께 정리해야 한다.
- `test/sdk_batch_module_translate.py`는 배치 기능의 Tkinter GUI 스크립트다. 수집되지 않아 스위트에
  영향이 없어 이번 삭제 범위에 넣지 않았으나 죽은 코드다.
- GUI 커버리지가 64건 줄었다. PySide6 기준으로 다시 쓰는 것은 별도 작업이다.
