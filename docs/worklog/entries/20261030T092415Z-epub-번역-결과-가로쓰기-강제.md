## 배경

GitHub 이슈 #67(v1.6.1): 세로쓰기 일본 소설 EPUB을 번역하면 결과 EPUB도 우종서·세로쓰기로 나왔다. 사용자는 이전처럼 가로쓰기 출력을 요청했다. 2026-10-25 XHTML 규격 복원에서 `class="vrtl"` 등 html/body 속성을 고의로 보존한 것이 직접 원인이다. OPF의 `page-progression-direction` rtl→ltr만으로는 본문 writing-mode가 바뀌지 않았다.

## 문제

- `reconstruct_chapter`가 원본 `vrtl`/`vltr`와 링크된 CSS를 그대로 두면 Calibre 계열 스타일시트의 `writing-mode: vertical-rl`이 번역문에도 적용된다.
- `vrtl` 클래스를 통째로 제거하면 2026-10-25에 고쳤던 `.vrtl img { max-width: 100% }`류 셀렉터가 다시 깨진다.
- CSS 파일만 두거나 클래스만 바꾸면 리더/원본 조합에 따라 한쪽이 빠진다.

## 결정과 근거

- 파싱(`process_chapter`)은 원본 속성을 그대로 두고, 재조립(`reconstruct_chapter`)에서만 가로쓰기로 정규화한다.
- html/body의 `vrtl`·`vltr` → `hltr`, `dir=rtl` → `ltr`, 인라인 `writing-mode: vertical-*` → `horizontal-tb`. `p-text` 등 다른 클래스는 유지한다.
- 헤드에 `writing-mode: horizontal-tb !important` 스타일을 넣어 인라인·잔여 규칙까지 덮는다.
- 번들 `.css`도 같은 규칙으로 writing-mode와 클래스 토큰을 치환한다. `.vrtl` → `.hltr`이므로 이미지 크기 셀렉터 매칭이 클래스 변경 후에도 유지된다. 단어 경계로만 치환해 `cover-vrtl-badge` 같은 식별자는 건드리지 않는다.
- 번역 파이프라인과 검토 탭 재패키징(`epub_provider`) 양쪽에 CSS 정규화를 넣었다. OPF rtl→ltr은 기존 그대로 둔다.
- 클래스 제거만 하거나 CSS만 손대는 단독 접근은 이미지 깨짐 또는 리더 클래스 의존을 남기므로 채택하지 않았다.

## 검증

- 2026-10-30: `pytest test/test_utils/test_epub_xhtml_standards.py` 7 passed. 재조립 시 `hltr`·가로쓰기 오버라이드, CSS 정규화, body `vrtl`+`dir=rtl` 변환 케이스를 포함한다.
- 관련 EPUB 필터 테스트: `test_epub_xhtml_standards` + `test_epub_overload_retry` + integration `-k epub` 합계 10 passed.

## 미해결

- 이미 `_epub_temp`에 저장된 이전 번역 XHTML은 이어하기 시 재정규화되지 않는다. 가로쓰기 적용을 보려면 `--force-new` 또는 해당 진행 폴더 삭제가 필요하다.
- 실제 세로쓰기 상용 EPUB으로 Calibre/리더 화면 확인은 하지 않았다.
- 사용자가 번역본도 세로쓰기를 원할 경우의 설정 옵션은 없다.
