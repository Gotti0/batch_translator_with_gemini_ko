## 배경

실행 로그에서 Gemini 키만 입력된 상태로 Claude CLI와 Codex CLI로 전환했는데 두 클라이언트가 모두 "API 키 지정 여부: True"로 생성되었고, Claude CLI는 환경변수 키가 로그인 세션보다 우선한다는 경고와 함께 실패했다.

## 문제

1. 설정 탭의 API 키 입력칸은 모든 프로바이더가 공유했고, 프로바이더를 바꿔도 내용이 남았다. 연결 테스트와 모델 조회용 설정은 현재 프로바이더가 Claude나 Codex이면 입력칸 첫 줄을 그 CLI의 키로 넘겼다.
2. 저장된 설정 경로에서도 클라이언트 팩토리가 CLI 전용 키가 없으면 Gemini 키 목록의 첫 키로 대체했다. 설정 탭이 CLI 전용 키를 아예 저장하지 않았기 때문에 이 대체는 사실상 항상 일어났다.
3. 두 경로 모두 결과적으로 Gemini 키가 ANTHROPIC_API_KEY나 OPENAI_API_KEY로 CLI에 들어갔다. 로그인 세션이 가려져 호출이 실패하고, CLI가 그 키로 인증을 시도하면 Google 키가 다른 회사 서버로 전송된다.
4. 역방향 오염도 있었다. Claude 화면에서 Anthropic 키를 입력하고 저장하면 그 키가 Gemini 키 목록을 덮어썼다.

## 결정과 근거

- 팩토리의 Gemini 키 대체를 제거했다. CLI 전용 키가 비어 있으면 로그인된 구독 세션을 쓴다는 의미가 되어, 입력칸 안내문("비워두면 로컬 구독 세션 사용")과도 일치한다.
- 입력칸은 하나로 두되 내용을 프로바이더별로 보관한다. 프로바이더마다 입력칸을 따로 두는 방법도 있으나, 폼 행과 가시성 분기가 늘어나고 기존 테스트와 위젯 매핑이 모두 바뀌므로 택하지 않았다. 보관 대상은 UI 메모리 안의 입력 문자열뿐이고, 입력칸이 원래 들고 있던 것 이상의 키를 새로 참조하지 않는다.
- 프로바이더와 설정 필드의 대응을 한 표로 두고, 저장·불러오기·연결 테스트·입력칸 표시 여부가 모두 이 표를 쓰게 했다. 표에 없는 프로바이더는 키를 쓰지 않는 것으로 보고 입력칸을 숨긴다. Antigravity CLI는 클라이언트가 키를 받지 않으므로 표에서 뺐다.
- 설정 불러오기는 프로바이더를 고르기 전에 키 보관함을 채우고 "현재 보이는 프로바이더"를 비워 둔다. 콤보 변경 시그널이 이전 입력칸 내용을 불러온 값 위에 덮어쓰지 않게 하기 위해서다.

## 검증

- 신규 테스트 4개(프로바이더 전환 시 키 교체와 복원, 저장 시 필드 분리, 저장된 CLI 키 복원, 팩토리가 Gemini 키를 빌리지 않음)가 수정 전 코드에서 모두 실패하고 수정 후 통과함을 확인했다.
- Antigravity 전환 테스트는 입력칸이 숨겨지고 Gemini로 돌아오면 다시 보이는지 확인하도록 바꿨다. 전체 스위트는 수정 후 통과했다.
- 2026-09-25 기준 사용자 설정 파일을 키 앞부분만 보이게 확인한 결과, Gemini 키 목록에 다른 회사 키가 섞여 있지 않았고 CLI 키 필드는 비어 있었다.
- 실제 GUI를 띄운 수동 확인과, 수정 후 Claude·Codex CLI가 로그인 세션으로 실제 호출에 성공하는지는 확인하지 않았다. 이 작업 세션 안에서 Claude CLI를 실행하면 세션 자체 인증이 우선해 원래 실패를 재현할 수 없었다.

## 미해결

- CLI 클라이언트는 비정상 종료 시 stderr가 있으면 stdout을 로그에 남기지 않는다. JSON 출력 모드에서는 실제 실패 사유가 stdout에 있을 수 있어 이번 같은 경고 한 줄에 원인이 가려진다.
