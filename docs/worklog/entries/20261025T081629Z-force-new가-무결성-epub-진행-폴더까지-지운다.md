## 배경

2026-10-25 Grok 프로바이더를 `main_cli.py`로 검증하던 중이었다. 같은 입력과 출력 경로로 앞서 Cursor 테스트를 돌린 뒤 `--force-new`로 다시 실행했는데, 무결성 모드가 프로바이더를 한 번도 호출하지 않고 2초 만에 이전 결과로 끝났다.

## 문제

- CLI의 새로 시작 경로는 입력 메타데이터와 출력 파일만 지웠다.
- 표준 모드는 메타데이터의 config_hash로 이어하기를 판단하므로 이것으로 충분했다.
- 무결성 모드는 출력 옆 `<출력>_integrity_temp/chunk_<i>.json`이 이어하기 근거다. 이 폴더는 검토 탭 캐시로 쓰려고 완료 후에도 보존하므로, 남아 있으면 모든 청크를 건너뛰었다.
- EPUB도 입력 옆 `<입력>_epub_temp/epub_metadata.json`으로 같은 방식으로 이어간다.
- 그래서 사용자가 프로바이더나 프롬프트를 바꿔 새로 번역해도 결과가 바뀌지 않았다.

## 결정과 근거

- 이어하기 근거를 지우는 일을 `AppService.discard_saved_progress`로 모았다. 메타데이터, 출력, 무결성 진행 폴더, EPUB 진행 폴더를 지우고 CLI가 이것을 부른다. 진행 폴더의 경로 규칙을 아는 쪽이 서비스 계층이라 CLI에 경로 공식을 복제하지 않았다. EPUB 경로도 `TranslationService.epub_temp_dir_for`로 꺼냈다.
- 번역 기억(`<파일명>_memory`)은 지우지 않는다. 번역 일관성을 위한 것이고, 지우면 다시 임베딩하는 비용이 든다.
- 진행 폴더 삭제에 실패하면 예외를 그대로 올린다. `ignore_errors`로 넘기면 `--force-new`인데도 조용히 이어하기가 되어 이번 문제가 재발한다.
- GUI 번역 버튼에는 새로 시작 선택지가 없고 항상 이어한다. 표준 모드는 설정 해시가 바뀌면 새로 시작하지만, 무결성 모드는 설정이 바뀌어도 진행 폴더에서 이어간다. 이 차이는 동작 설계 문제라 이번에 바꾸지 않았다.

## 검증

- 2026-10-25 전체 테스트: 586 passed, 7 skipped. 신규 `test_force_new_progress.py` 4건이 포함된다. 그중 하나는 예전처럼 메타데이터와 출력만 지우면 재요청이 0회이고 이전 결과가 남는 것을 재현하고, 다른 하나는 새 경로에서 4개 청크가 모두 다시 요청되는 것을 확인한다.
- 실제 CLI 실행(Claude CLI haiku, integrity 모드): 이전 진행 폴더가 남아 있는 상태에서 `--force-new`를 실행했다. "이전 진행 상태 폴더 삭제"가 로그에 찍혔고, 진행 상태 로드 로그가 없었으며, 실호출 11초 뒤 번역문이 바뀌었다.

## 미해결

- GUI에서 무결성 번역을 처음부터 다시 하려면 검토 탭 초기화나 진행 폴더 수동 삭제가 필요하다.
- 배치 모드의 CLI 경로(`--batch-*`)는 새로 시작 판단을 거치지 않으므로 이번 변경의 대상이 아니다.
- EPUB 진행 폴더 삭제는 단위 테스트로만 확인했고, 실제 EPUB 번역으로 돌려 보지는 않았다.
