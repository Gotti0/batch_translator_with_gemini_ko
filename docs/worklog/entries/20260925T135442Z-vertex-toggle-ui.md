## 배경

Gemini 프로바이더의 Vertex AI 모드는 백엔드 인증 경로와 설정 저장이 모두 연결되어 있었으나, GUI에서 체크박스를 눌러도 서비스 계정·GCP 프로젝트·GCP 위치 입력칸이 나타나지 않아 미구현처럼 보였다.

## 문제

1. 토글 핸들러가 `stateChanged`가 넘기는 int를 Qt.Checked와 비교했다. PySide6 6.4 이후 Qt enum은 파이썬 Enum이라 int와의 동등 비교가 항상 False이고(6.10.1에서 확인), 사용자가 클릭한 경로에서는 켜짐 판정이 한 번도 참이 되지 않았다. 설정 로드 경로만 checkState() enum을 넘겨 우연히 동작했다.
2. 입력칸 행 표시(setRowVisible)는 프로바이더 변경 핸들러에만 있어서, 판정이 맞더라도 체크 직후에는 행이 보이지 않았다.
3. API 키 입력칸 잠금은 토글 핸들러에만 있어서, Vertex가 켜진 채 다른 프로바이더로 바꾸면 API 키 칸이 잠긴 채 남을 수 있었다.

## 결정과 근거

- 시그널 인자를 버리고 isChecked()로 위젯 상태를 직접 읽는다. enum 변환으로 비교를 맞추는 방법도 있으나, 로드 경로와 시그널 경로가 서로 다른 타입을 넘기는 구조 자체가 원인이므로 인자에 의존하지 않는 쪽을 택했다.
- 행 표시·활성화·API 키 잠금을 한 함수로 모으고 프로바이더 변경과 토글이 모두 이를 호출하게 했다. 판정은 "Gemini이면서 체크됨"으로 두어 다른 프로바이더에서는 Vertex 상태가 남아 있어도 영향을 주지 않는다.
- 트레이드오프: 기존에는 Vertex가 켜진 설정을 불러올 때 서비스 계정 경로가 비어 있으면 시작 시 안내창이 떴다. 설정 로드 중에는 체크박스 시그널을 막고 상태만 반영하도록 바꿔, 안내창은 사용자가 직접 체크할 때만 뜬다. 매 실행마다 뜨는 모달은 경로를 아직 정하지 않은 사용자에게 소음이고, 입력칸이 보이는 것만으로 누락을 알 수 있다고 판단했다.

## 검증

- 신규 회귀 테스트 3개(체크 시 행 표시와 API 키 잠금, 비 Gemini 프로바이더에서 숨김, 로드 시 안내창 없음) 중 2개가 수정 전 코드에서 실패하고 수정 후 통과함을 확인했다.
- 수정 후 전체 스위트를 처음 돌렸을 때 배치 설정 테스트가 멈췄다. Vertex를 체크하는 기존 테스트가 이제 제대로 뜨는 모달 안내창에서 대기한 것으로, 버그가 모달을 가리고 있었다. 해당 테스트에서 안내창을 패치해 억제했고 이후 전체 스위트가 통과했다.
- 실제 GUI를 띄워 클릭하는 수동 확인은 하지 않았다.

## 미해결

- Vertex 모드의 실제 API 호출(서비스 계정 JSON과 ADC 경로)은 이번 작업에서 검증하지 않았다.
