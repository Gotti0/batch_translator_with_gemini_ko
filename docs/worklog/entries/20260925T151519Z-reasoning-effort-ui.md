## 배경

추론 강도 옵션 명세와 호출 연결이 앞선 작업으로 들어갔지만 설정 탭에서는 Gemini의 Thinking Level·Budget만 조절할 수 있었다. 다른 프로바이더를 고르면 두 행이 비활성 상태로 남았다.

## 문제

1. 설정 탭의 입력칸 하나를 여러 프로바이더가 공유하는 구조가 API 키 외에도 남아 있었다.
2. CLI 실행 경로 칸은 칸이 비었거나 다른 CLI의 기본 이름일 때만 바꿨다. 그래서 Claude에 지정한 전체 경로가 Codex로 전환해도 남아, 연결 테스트와 저장에 그대로 쓰였다.
3. 저장 시 Thinking Level·Budget은 칸이 비활성이면 None으로 썼다. 다른 프로바이더를 고른 채 저장하면 Gemini에서 고른 thinking_level이 지워지고 다음 Gemini 번역은 기본값으로 돌아갔다.

## 결정과 근거

- API 키에 쓰던 프로바이더별 보관·교체 방식을 CLI 실행 경로와 추론 강도까지 넓혀, 프로바이더를 바꿀 때 세 값을 함께 보관하고 교체한다. 입력칸마다 따로 두는 방식은 폼 행과 가시성 분기가 늘어 택하지 않았다.
- Gemini는 기존 Thinking Level·Budget 행을 유지하고, 다른 프로바이더는 새 "추론 강도" 행 하나를 쓴다. 한 행으로 합치면 Gemini의 기존 설정 키와 기본값 규칙(기본값 항목 없이 high)을 바꿔야 한다.
- 행 표시 규칙은 설정 탭에 박혀 있던 모델 이름 분기 대신 추론 옵션 명세를 따른다. 해당하지 않는 행은 비활성으로 두지 않고 숨긴다.
- Gemini 추론 설정은 Gemini를 고른 상태에서만 쓴다. Gemini 3에서는 level만, 그 외에는 budget만 쓰고 나머지는 건드리지 않는다. 예전에는 반대쪽 값을 None으로 지웠다.

## 검증

- 신규 테스트 6개: 프로바이더·모델별 행 표시와 선택 항목, 추론 강도 프로바이더별 보관과 저장, 저장된 추론 강도 복원, 다른 프로바이더에서 저장해도 Gemini thinking_level 유지, CLI 실행 경로 프로바이더별 보관과 저장, 저장된 경로 복원. 이 중 thinking_level 유지와 CLI 경로 보관 테스트는 수정 전 코드에서 각각 None과 Claude 경로로 실패했다. 전체 스위트가 통과했다.
- 실제 설정으로 메인 창을 화면 없는 모드로 띄워 Claude CLI 선택 시 "추론 강도" 행만 보이고 선택 항목이 명세와 같음을 확인했다. 글꼴이 들어간 실제 창과 클릭 동작은 확인하지 않았다.

## 미해결

- 추론을 지원하지 않는 Ollama 모델에서 think 값을 고르면 서버가 거부할 수 있으나, UI는 모델별 지원 여부를 모른다.
