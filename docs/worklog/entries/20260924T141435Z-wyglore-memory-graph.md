## 배경

Voyage 임베딩 번역 기억은 의미가 가까운 번역 문단만 찾는다. 소설 번역의 일관성 문제는 주로 인물 단위(말투, 호칭, 1인칭, 관계)에서 생기고, 이는 문단 유사도로 잘 잡히지 않는다. RisuAI 플러그인 WygLore Leaf의 연상 기억 설계를 번역 작업에 맞게 옮겼다.

## 문제

문단 유사도 기반 기억은 인물 단위의 일관성(말투, 호칭, 1인칭, 관계)을 잘 잡지 못한다. 소설 번역의 일관성 문제는 주로 이 인물 단위에서 생긴다.

## 결정과 근거

- **가지 3종** (`domain/memory_graph.py`): 캐논(용어집, 고정·감쇠 없음), 인물(추출된 성장 가지), 에피소드(번역된 문단). 캐논은 용어집이 기준이며 자동 추출이 덮지 않는다 (캐논과 성장의 분리).
- **점화**: 이름·별칭이 원문에 직접 나오면 1.0 (직접 호명). 에피소드는 임베딩 유사도를 씨앗으로 쓴다.
- **확산**: 깊이 프리셋 fast(0홉) / balanced(1홉) / deep(2홉), 홉마다 가중치 × 0.5, 이웃 상한 20.
- **헵 강화**: 같은 청크에 등장하거나 함께 주입된 가지끼리 연결 +0.1. 자주 함께 나온 인물은 한쪽만 호명돼도 떠오른다.
- **호박**: 성장 가지는 30청크 동안 점화되지 않으면 가라앉아 약한 확산으로는 닿지 않는다. 삭제하지 않으며, 직접 호명되거나 deep 프리셋의 약한 연결로 깨어난다.
- **시간 축은 청크 번호**: 감쇠를 전역 틱이 아니라 저장된 마지막 점화 청크와의 거리로 계산한다. 병렬·배치에서 청크가 순서 없이 처리되어도 recall 결과가 같다. recall은 상태를 바꾸지 않고, 청크 기록(close_chunk) 때만 강화·점화 기록이 갱신된다.
- **시간 서술어**: 청크 거리를 "바로 앞", "12청크 전", "오래 전 · 호박 속"으로 바꿔 인물 메모와 예시에 붙인다.
- **두 결의 합류**: 직접 호명된 가지가 먼저, 그다음 점화 강도 순.
- **투 트랙 인물 메모 추출** (`domain/memory_extractor.py`): 번역된 청크(원문+번역문)에서 말투·호칭·1인칭·관계를 JSON으로 뽑는다. 추출 전용 클라이언트(별도 스케줄러)로 뒤에서 실행해 번역 속도에 영향이 없고, 동시 2개로 제한한다. 이름·별칭이 겹치면 기존 가지에 흡수하고 머지 기록을 남긴다. 원문 닻으로 이름이 처음 나온 줄을 보관한다. 기본값은 꺼짐.
- **주입**: `<translation_memory>` 안에 `<characters>`(인물 메모)와 `<examples>`(시간 표시 번역 예시). 캐논은 기존 용어집 경로로 들어가며, 연결로 떠오른 용어도 의미 기반 용어로 더한다. "용어집과 다르면 용어집을 따르라"를 명시한다.
- **기억뜰 보기**: 설정 탭에서 인물 가지(메모, 마지막 등장, 호박 여부, 원문 닻)와 최근 자동 흡수 기록을 본다.

## 검증

- 그래프 테스트 11개(시간 서술어, 별칭 직접 호명, 확산·강화·깊이, 헵 강화, 호박과 깨어남, 자기 청크 제외, 별칭 흡수·머지 기록·원문 닻, 캐논 동기화·저장/로드, 주입 형식, 추출 응답 정규화, 추출 호출).
- 통합 테스트: 청크 0에서 추출된 인물 메모가 마지막 청크 요청에 주입, 추출 실패 시 번역 계속, 기억뜰 개요.
- 설정 탭: 깊이·추출 설정 저장/로드, 기억뜰 대화상자.
- 전체: 367 passed, 7 skipped.
- 실제 모델로 추출 품질과 번역 일관성 개선은 검증하지 않았다.
