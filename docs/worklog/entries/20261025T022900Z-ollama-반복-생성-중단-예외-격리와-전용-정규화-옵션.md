## 배경

2026-10-25 GitHub 이슈 #59에서 Ollama 로컬 LLM을 사용해 일본어 EPUB 소설을 번역할 때, 동일 문자가 길게 반복되는 의성어(예: `『グガガァァァァァァァァッッッッ!!』`)가 포함된 챕터에서 번역 오류가 발생하고 해당 챕터 전체가 일본어 원문으로 보존되는 문제가 제보되었다.

## 문제

2026-10-25 로컬 Ollama 0.40.10과 qwen3.5:9b 모델로 재현한 결과, 반복 의성어를 처리하던 모델이 `아아아…`를 끝없이 출력하는 토큰 퇴화 루프(degeneration loop)에 빠지면 Ollama 서버가 생성을 강제 중단하고 HTTP 500 `prediction aborted, token repeat limit reached` 에러를 반환했다.
무결성 번역 파이프라인(`_translate_integrity_chunk_with_retry`)은 오직 콘텐츠 안전(검열) 예외만 이진 분할로 복구하도록 설계되어 있어, 일반 API 오류로 올라온 이 500 에러를 분할하지 않고 상위로 던졌다. 그 결과 EPUB 번역은 챕터 단위 포괄 예외 처리가 발생하여 앞서 번역한 청크를 포함한 챕터 전체를 원문으로 기록했고, 텍스트 무결성 모드는 작업 전체가 비정상 중단되었다. 오류 로그에도 예외 타입과 역추적(traceback) 없이 잘린 메시지만 찍혀 원인 파악이 어려웠다.

## 결정과 근거

- `BtgApiRepetitionException`을 신설하고 OllamaClient의 HTTP 500 응답 메시지에 `token repeat limit`이 포함될 때 분류 발생시킨다. 일반 통신 실패나 검열 실패와 분리해야 전용 격리 복구를 적용할 수 있다.
- 반복 생성 중단은 검열 분할 예산(`max_content_safety_split_attempts`)을 따르지 않고 의심 줄 격리(`_isolate_repetition_units`) 경로로 처리한다. 기존 검열 분할은 기본 깊이 2에서 멈추므로 200줄 청크라면 50줄 조각이 통째로 원문으로 폐기되어, "실패한 특정 의성어 문장만 원문으로 두고 나머지는 정상 번역"하려는 목표를 달성할 수 없다.
- 의심 줄 격리는 5회 이상 연속 동일 문자나 4회 이상 2문자 패턴(`_REPEATED_RUN_RE`)을 탐색한다. 의심 줄이 식별되면 정상 줄들은 한 번에 일괄 재시도하고 의심 줄만 1줄씩 단독 요청한다. 단독 요청에서도 반복 중단이 재발하면 그 줄만 원문으로 보존하고 경고 로그를 남긴다. 정규식에 걸리지 않은 예외는 이진 분할로 좁혀 최종 단일 항목 원문 보존으로 수렴시킨다.
- 사전 예방책인 입력 정규화는 Gemini 등 원작 표기 유지가 중요한 타 프로바이더에 영향을 주지 않도록 Ollama 전용 옵션(`ollama_normalize_repeated_chars`, 기본값 True)으로 분리 구현했다. 5회 이상 반복 문자를 최대 4개로, 4회 이상 2문자 반복을 3회로 축약하여 프롬프트를 전송한다.
- EPUB 챕터 처리 오류 로그에 예외 타입명과 `exc_info=True`를 추가하여 실패 원인을 투명하게 기록하도록 개선했다.
