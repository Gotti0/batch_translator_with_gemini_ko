## 배경

이전 항목은 설정 탭 Vertex 토글을 고치면서 백엔드 인증 경로가 연결되어 있다고 보고 실제 호출은 검증하지 않았다. 서비스 계정 JSON으로 실호출을 해 보니, 클라이언트에 JSON을 직접 넘기면 asia-northeast3와 global 모두에서 모델 조회와 번역이 성공했지만 앱이 쓰는 팩토리 경로에서는 실패했다.

## 문제

1. 팩토리는 Vertex가 켜져 있고 서비스 계정 경로가 있으면 인증 정보로 경로 문자열 자체를 넘겼다. 클라이언트는 문자열을 JSON으로 파싱해 서비스 계정이면 Vertex, 아니면 API 키로 해석하므로 경로가 API 키가 되었고, 호출은 Gemini Developer API에서 API_KEY_INVALID로 거부됐다. 설정 로드 경로는 파일을 읽어 내용을 넘기고 있었으나 팩토리가 이를 경로로 덮어썼다.
2. 클라이언트는 설정의 Vertex 토글을 받지 않고, 인증 정보가 서비스 계정인지와 GOOGLE_GENAI_USE_VERTEXAI 환경 변수로만 Vertex 여부를 정했다. 서비스 계정 없이 토글만 켜면 설정 로드는 "ADC 사용"을 로그에 남기지만 팩토리가 설정의 API 키를 채워 넣어, 사용자가 모르는 사이 API 키 쿼터로 호출되거나 API 키가 없으면 초기화에 실패했다.

멀티 프로바이더 도입으로 팩토리가 생긴 뒤 Vertex 모드는 앱에서 한 번도 동작하지 않았던 것으로 보인다. 이전 항목의 "백엔드 인증 경로가 연결되어 있다"는 판단은 틀렸다.

## 결정과 근거

- 서비스 계정 파일 읽기를 팩토리에 둔다. 앱이 이미 넘기는 인증 정보를 우선하는 방법도 있었으나, 헬스체크·모델 목록 조회·인물 메모 추출기는 인증 정보 없이 설정만 팩토리에 넘기므로 그 경로들이 계속 깨진다.
- 클라이언트에 Vertex 사용 여부를 인자로 넘긴다. 켜져 있으면 서비스 계정이 있을 때 그것을, 없으면 ADC를 쓰며 API 키는 받아도 버린다. 환경 변수 판정은 그대로 두어 기존 사용 방식을 유지했다.
- 버린 접근: 처음에는 서비스 계정 파일을 읽지 못하면 경고만 남기고 넘겨받은 인증 정보나 설정의 API 키로 넘어가게 했다. 설정 로드의 기존 대체 동작과 맞춘 것이었으나, 경로 오타 하나로 Vertex 대신 API 키 쿼터로 조용히 바뀌는 문제 2와 같은 결과가 되어 버렸다. 지금은 경로를 지정했는데 파일이 없거나 서비스 계정이 아니면 오류를 낸다. 넘겨받은 인증 정보가 서비스 계정일 때만 그것을 쓴다. ADC로 넘어가지 않는 것도 같은 이유로, 사용자가 지정한 것과 다른 계정으로 호출되지 않게 하려는 것이다.
- ADC는 클라이언트 생성 시 미리 읽는다. SDK는 첫 요청 때 읽으므로 ADC가 없으면 번역 도중에야 드러난다. 미리 읽으면 연결 테스트에서 설정 방법을 담은 오류로 알릴 수 있고, ADC에 담긴 프로젝트를 기본 프로젝트로 쓸 수 있다. 그래서 설정 로드에서 Vertex+ADC일 때 프로젝트 ID를 요구하던 조건도 뺐다.

## 검증

- 팩토리 회귀 테스트 5개를 추가했다(서비스 계정 경로만 준 경우, 파일이 없을 때 넘긴 서비스 계정으로 대체, 토글만 켜면 API 키가 아닌 ADC, 쓸 수 없는 서비스 계정 경로는 오류, ADC가 없으면 오류). 각 단계에서 추가한 테스트가 해당 수정 전 코드에서 실패하고 수정 후 통과하는 것을 확인했다. 전체 스위트가 통과했다.
- 수정 후 팩토리로 실제 Vertex(global)에 호출했다. 서비스 계정 경로 지정, ADC가 서비스 계정을 가리키게 한 토글만 켠 경우(프로젝트 ID는 ADC에서 결정) 모두 헬스체크와 gemini-2.5-flash 번역이 성공했다. 두 경우 모두 설정에 넣은 가짜 API 키는 쓰이지 않았다.
- 이 PC의 gcloud 사용자 ADC로도 호출했다. Vertex 모드로 요청이 나갔으나, ADC의 할당량 프로젝트가 삭제된 프로젝트여서 모델 조회가, 사용자 계정의 예측 권한이 없어 번역이 거부됐다. 코드가 아니라 로컬 계정 설정 문제로 판단했다.
- 없는 서비스 계정 경로를 주면 클라이언트 생성이 파일명을 담은 오류로 실패하는 것을 실제로 확인했다.
- GUI에서 Vertex를 켜고 번역을 돌리는 확인은 하지 않았다.

## 미해결

- 기본 위치 asia-northeast3에서는 조회되는 모델이 7개이고 global에서는 27개였다. gemini-3 계열을 쓰려면 위치를 global로 두어야 할 가능성이 크지만 기본값은 바꾸지 않았다.
- global에서 gemini-3.8-flash 단문 번역이 약 270초 걸렸다. Thinking Level HIGH 적용과의 관계는 확인하지 않았다.
- Vertex가 켜져 있어도 GUI의 API 키 입력값은 설정에 남는다. 이제 쓰이지 않지만, 배치 번역 등 다른 경로에서 이 값을 읽는지는 전부 점검하지 않았다.
