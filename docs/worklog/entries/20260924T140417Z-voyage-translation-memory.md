## 배경

청크는 서로 모른 채 번역되고, 용어집은 키워드가 원문에 그대로 있을 때만 청크당 3개까지 들어간다. 그래서 앞에서 정한 호칭·말투가 뒤에서 흔들리고, 별칭·변형 표기는 용어집을 놓친다.

## 문제

청크 사이에 번역 맥락이 전달되지 않아 앞에서 정한 호칭·말투가 뒤 청크에서 흔들린다. 용어집 주입은 키워드가 원문에 그대로 있을 때만 동작해 별칭·변형 표기를 놓친다.

(2026-09-26 보완: 형식 검증을 통과시키려고 추가한 섹션이며, 원 기록 본문의 내용을 옮겨 적었다.)

## 결정과 근거

- **Voyage REST 직접 호출** (`infrastructure/embedding_client.py`): 공식 SDK 의존성 없이 `requests`로 `POST /v1/embeddings`. 요청당 1,000개·모델별 토큰 한도(글자 수로 보수 추정, 80% 예산)로 묶고, 429·5xx·네트워크 오류만 지수 백오프로 재시도한다. 실제 API의 오류 본문(`{"detail": ...}`, 401)을 확인해 메시지를 맞췄다.
- **기본 모델 voyage-4-lite, 512차원**: 1M 토큰당 $0.02, 무료 200M 토큰. 소설 한 권(100만 자) 인덱싱은 약 $0.02.
- **번역 전 한 번만 인덱싱, 번역 중에는 API 미호출**: 청크 검색의 쿼리 벡터는 그 청크 문단의 저장된 벡터를 재사용한다. 번역 속도에 영향이 없고 Voyage 장애가 번역을 멈추지 않는다.
- **로컬 저장소** `<파일명>_memory/` (vectors.npy, items.jsonl, meta.json): 같은 모델·차원이면 내용 해시가 같은 문단은 다시 임베딩하지 않는다. 모델·차원이 바뀌면 새로 만든다. 저장소가 없어져도 청크 백업 파일에서 번역문을 되살린다.
- **문단 짝짓기**: 인덱싱과 기록이 같은 `split_paragraphs` 규칙을 쓰고, 원문·번역 문단 수가 같을 때만 순서대로 짝짓는다. 다르면 그 청크는 예시로 쓰지 않는다(불일치 수를 stats에 남김).
- **주입**: `build_translation_request`(실시간·배치 공용)에서 예시 블록을 `{{translation_memory}}` 자리에, 없으면 시스템 지시문 끝에 XML 블록으로 넣는다. 동적 용어집 주입에는 의미 기반 용어를 더한다(기존 키워드 일치 유지, 더한 수만큼 항목 한도 증가).
- **실패 격리**: 임베딩 준비 실패, 검색·기록 예외는 경고만 남기고 기억 없이 번역한다.
- **기본값 꺼짐**: 원문이 외부로 전송되므로 사용자가 켜야 동작한다.

## 검증

- 임베딩 클라이언트 단위 테스트 10개(요청 본문, 1,000개 분할, 429/5xx/네트워크 재시도, 인증·요청 오류 비재시도, 응답 순서·개수), 실제 Voyage API에 잘못된 키로 호출해 401 메시지 확인.
- 기억 저장소 테스트 4개(문단 분할, 해시 캐시·재오픈·모델 변경, 기록·불일치·검색·자기 청크 제외·기준값, 용어 검색).
- AppService 통합 테스트 5개: 뒤 청크가 가장 비슷한 앞 청크의 번역을 예시로 받음, 자리표시자 주입, 저장소 삭제 후 백업 파일로 복원·재임베딩 없음, 임베딩 실패 시 기억 없이 번역, 꺼져 있으면 아무것도 호출하지 않음.
- 의미 기반 용어 주입 테스트, 설정 탭 저장·로드 테스트.
- 전체: 345 passed, 7 skipped.
- 실제 Voyage 키로 번역 품질(호칭·말투 일관성)은 검증하지 않았다. 일본어 원문의 실제 토큰화 비율과 문단 불일치 비율도 실측이 필요하다.

## 미해결

- 실제 Voyage 키로 번역 품질(호칭·말투 일관성) 개선을 검증하지 않았다.
- 일본어 원문의 실제 토큰화 비율과 문단 불일치 비율은 실측이 필요하다.
