## 배경

무결성 모드는 표준 모드의 기억 준비보다 앞에서 분기해 번역 기억이 전혀 적용되지 않았다. 그런데 무결성 모드는 줄마다 id가 있어 원문 문단과 번역을 가장 정확하게 짝지을 수 있는 모드다. 표준 모드는 번역 문단 수가 원문과 다르면 그 청크를 기억에 남기지 못한다.

## 결정과 근거

- **청크 경계 공유**: `TranslationService.split_integrity_chunks()`로 무결성 청크 분할을 꺼내, 번역과 인덱싱이 같은 경계(청크 번호)를 쓴다.
- **줄 번호 기반 짝짓기**: `split_paragraph_groups()`는 기존 `split_paragraphs()`와 같은 문단을 만들면서 문단마다 원래 줄 번호를 함께 준다(`split_paragraphs`는 이제 이 함수를 쓴다. 무작위 입력 20만 개로 이전 구현과 결과가 같음을 확인). `record_aligned_translation()`은 원문 문단의 줄 번호를 그대로 번역 줄에 적용하므로 문단 수가 달라도 버리지 않는다. 번역이 빠진 줄이 있는 문단만 건너뛴다.
- **검색은 원문 줄로**: 무결성 요청의 `{{slot}}`은 JSON이라 해시가 맞지 않는다. 기억 검색·의미 기반 용어 검색에는 청크의 원문 줄을 이어 붙인 텍스트를 쓴다. 분할 재시도의 조각은 온전히 들어 있는 문단만 맞는다.
- **주입 위치**: `{{translation_memory}}` 자리표시자가 있으면 그 자리(프리필 히스토리 포함), 없으면 JSON 강제 지시문 뒤에 붙인다.
- **이어하기**: 기억 폴더가 없거나 새로 켰을 때 `<출력>_integrity_temp/chunk_<i>.json`에서 끝난 청크를 되살린다.
- **청크 경계가 바뀌어도 번역 유지**: 재인덱싱 때 (청크, 해시, 문단 위치)가 같지 않아도 같은 해시의 번역이 있으면 이어 쓴다. 표준 ↔ 무결성 모드를 오가도 쌓인 기억을 잃지 않는다.
- **인물 메모 추출**: 무결성 청크도 원문·번역 줄을 이어 붙여 추출기에 넘기고, 끝나기 전에 남은 추출을 기다린다.
- **EPUB**: 기억을 쓰지 않으므로 앞 작업의 기억이 남아 섞이지 않게 떼어 둔다.

## 검증

- 저장소: 줄 번호 보존, 줄 기반 짝짓기(문단 수 불일치·번역 누락), 청크 경계 변경 시 번역·벡터 재사용.
- 요청 조립: 무결성 청크의 기억·의미 기반 용어 검색이 원문 줄로 이뤄지고, 기억 블록이 시스템 지시문 끝에 붙음.
- 통합(AppService, 무결성 모드): 마지막 청크가 청크 0의 번역을 예시로 받음, 자리표시자 주입, 기억 폴더 삭제 후 임시 결과에서 복구(모델 호출 0회), 인물 메모 추출·주입, 꺼져 있으면 동작 불변.
