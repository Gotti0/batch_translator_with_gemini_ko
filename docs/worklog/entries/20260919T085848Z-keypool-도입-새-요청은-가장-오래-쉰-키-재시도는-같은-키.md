## 배경

RPM 제어 리팩터 T4다. 기존에는 키 하나를 성공하는 동안 계속 쓰다가(sticky), 오류가 나면 그 키로
최대 6회 재시도한 뒤 다음 키로 넘어가 모든 키를 돌았다. 503이 계속되면 키 45개 × 6회 = 270회까지
시도했고, 503도 RPD를 쓰므로 과부하 한 번에 여러 키의 하루 한도가 낭비될 수 있었다.

사용자가 정한 규칙: 새 요청은 가장 오래 쉰 키로 보낸다. 재시도는 같은 키로 보낸다(어느 키를 소진했는지
알아야 하므로). 다른 키로 넘어가는 것은 할당량 소진일 때뿐이다.

## 문제

1. 키를 언제 고를지. 요청이 슬롯을 기다리는 동안 미리 고르면, 대기열의 요청이 모두 같은 "가장 오래 쉰
   키"를 집는다.
2. 재시도를 다 쓴 일시 오류를 어떤 예외로 끝낼지. 호출부(TranslationService, GlossaryService)는
   `GeminiAllApiKeysExhaustedException`을 받으면 작업 전체를 멈춘다. 재시도가 같은 키 안에서 끝나면
   "모든 키 소진"은 사실이 아니다.

## 결정과 근거

- 키는 스케줄러 슬롯 안, 실제로 보내는 순간에 고른다. 동시에 대기하던 요청 4개가 키 A, B, C, A로
  고르게 나뉜다.
- "가장 오래 쉰" 순서는 시계가 아니라 사용 순번 카운터로 정한다. 시계는 쿨다운에만 쓰고, 스케줄러와 같은
  시간축을 공유한다(`RequestScheduler.clock`).
- 일시 오류(503, 분당 429, timeout 등)는 같은 키로 요청당 `max_retries`회까지만 재시도하고, 다 쓰면
  새 예외 `GeminiRetriesExhaustedException`으로 끝낸다. 이 예외는 `GeminiAllApiKeysExhaustedException`을
  상속한다. 호출부의 작업 중단 동작을 바꾸지 않기 위해서다.
  - **버린 대안: 일반 `GeminiApiException`으로 끝내 청크만 실패시키고 작업은 계속.** 서킷브레이커(T5b)가
    없는 상태에서 과부하가 이어지면, 다음 청크들이 청크마다 6회씩 계속 RPD를 쓴다. 청크가 100개면
    600회로, 이전(270회 후 중단)보다 나빠진다. 작업을 멈추는 쪽이 더 보수적이다.
  - 결과적으로 과부하 시 작업이 멈출 때까지의 시도는 최대 270회에서 6회로 줄었다.
- 할당량 소진은 키를 쿨다운(기존과 같은 100초)에 넣고 다른 키로 넘어가며, 일시 오류 재시도 예산을 쓰지
  않는다. 모든 키가 쿨다운이거나 이 요청에서 실패했으면 `GeminiAllApiKeysExhaustedException`이다.
- 요청 오류(400·401·403 계열)는 잘못된 키일 수 있어 기존처럼 아직 안 쓴 키로 넘어가되, 쿨다운에는
  넣지 않는다. 요청 자체의 문제인지 키 문제인지는 T5의 분류기에서 가른다.
- 키 전환 시 `키 전환: 키#a → 키#b`를 로그에 남긴다.
- `list_models`는 메타데이터 조회라 쿼터와 무관하므로, 실패하면 이 조회에서 아직 안 쓴 키로 한 번씩
  다시 시도한다(기존 동작과 같음).

## 검증

- KeyPool 단위 테스트 9개, 특성 테스트 재작성(sticky → LRU, 전 키 순환 → 같은 키 재시도 후 실패)과
  신규 6개(대기열 키 분배, 재시도 키 고정, 전환이 예산을 쓰지 않음, 쿨다운 건너뛰기, 전 키 소진, 요청 오류 전환).
- 변형 확인: 재시도마다 새 키, LRU 대신 첫 키 고정, 쿨다운 무시, 전환이 재시도 예산 소모 — 모두 잡힌다.
- 작업 중 `test_backoff_happens_outside_the_slot`가 실패했다. 테스트 스크립트가 "키마다 첫 호출은 503"
  이라 두 번째 요청도 새 키에서 503을 맞았기 때문이다. 코드가 아니라 테스트 가정이 sticky 키에 기대고
  있었고, 첫 키의 첫 호출만 실패하게 고쳤다.
- 가짜 키 2개로 실제 SDK 경로 확인: 키#1 400 → `키 전환: 키#1 → 키#2` → 키#2 400 → 전 키 소진 예외.
- 전체 pytest: 93 passed, 새 실패 없음.

## 미해결

- RPD와 RPM 소진을 구별하지 않는다. 둘 다 100초 쿨다운이라, 하루 한도가 끝난 키도 100초 뒤 다시 골라져
  슬롯 하나를 쓴다. `quotaId`(PerDay/PerMinute)로 구별할 수 있음은 확인했으나 이번 범위에 넣지 않았다.
- 503 재시도 1회와 서킷브레이커는 T5b, 500 검열 판정은 T5.
