## 배경

2026-10-10 실사용 로그에서 무결성 배치 79청크를 수거(성공 75, 검열 1, 누락 3)한 직후, 인물 메모 추출 75건이 수거 동작 안에서 대기했다. 추출은 실시간 API로 나가고 전역 스케줄러(RPM 2) 때문에 한 번에 하나씩 처리됐다. thinking level 기본값 HIGH가 걸려 건당 30초에서 4분 30초가 걸렸다. 13분 동안 10건을 처리했고, 그동안 GUI의 마무리 버튼(실시간 마무리, 재제출, 그대로 저장)이 잠겨 있었다.

## 문제

인물 메모 추출은 순차 실시간 번역을 전제로 설계됐다. 앞 청크에서 뽑은 메모가 뒤 청크 요청에 주입되어야 가치가 있고, 추출 요청은 번역 속도만큼 띄엄띄엄 들어온다고 가정한다. 09-24 배치 연동은 이 전제를 검토하지 않고 수거 콜백에 기록과 추출 예약을 함께 붙였고, 수거 뒤에 추출 완료 대기를 넣었다. 목표는 배치 결과가 기억에서 빠지지 않게 하는 것이었다.

배치 요청은 제출 때 한꺼번에 만들어지므로, 이번 배치에서 뽑은 메모는 같은 배치의 어떤 청크에도 들어가지 못한다. 혜택을 보는 곳은 남은 청크(이번 경우 4개)의 마무리나 재제출뿐이다. 결과가 수거 때 한꺼번에 도착해 추출이 몰리는데, 대기 위치가 최종 병합이 아니라 중간 단계인 수거라서 수거 동작이 수십 분 끝나지 않는다. 추출기는 배치용 유료 키를 쓰지 않고 순환 키로 정가 실시간 호출을 한다. 번역은 할인된 배치로 하고, 그보다 단순한 후처리를 정가로 하나씩 처리하는 역전이 생긴다.

## 결정과 근거

- 배치 수거 콜백은 번역 기억에 예시로 기록만 하고 추출을 예약하지 않는다. 배치용 기억을 준비할 때도 추출기를 만들지 않는다. 기억 준비 로그에는 "끔 (배치 결과는 추출하지 않음)"이라고 남겨 설정이 켜져 있는데 왜 꺼졌는지 보이게 했다.
- 수거 경로(시작 버튼의 조회, 폴링·상태 확인 버튼)에서 추출 대기를 없앴다. 최종 병합과 무결성 출력 쓰기 직전의 대기는 남겼다. 실시간과 공유하는 경로이고, 중단된 실시간 실행이 남긴 작업을 받을 수 있어서다. 배치에서는 기다릴 작업이 없으므로 비용이 없다.
- 버린 접근: 추출은 유지하되 수거에서 기다리지 않고 뒤에서 돌리는 방식.
  - 사용자가 곧바로 실시간 마무리를 누르면, 별도 스케줄러를 쓰는 추출 요청이 번역 요청과 같은 순환 키 풀에서 겹친다. 무료 키 여러 개를 동시에 부르지 않는다는 원칙에 어긋난다.
  - 재제출이나 마무리가 기억을 새로 준비하면, 남은 추출 작업이 옛 저장소 객체에 쓰고 같은 그래프 파일을 저장해 새 저장소의 기록을 덮어쓸 수 있다.
  - 비용 대비 혜택(추출 75건 대 남은 4청크)은 달라지지 않는다.
- 다른 후보였던 "추출 자체를 배치 요청으로 제출"과 "남은 청크 처리 직전에만 추출"은 이번 범위에서 하지 않았다.
- 트레이드오프: 배치로 번역한 청크에는 인물 메모가 생기지 않는다. 기억뜰에서 배치 구간의 인물이 비고, 남은 청크를 마무리할 때 인물 메모 주입이 없다(번역 예시 주입은 그대로다). 실시간 마무리가 번역하는 청크부터는 다시 추출한다.

## 검증

- 새 통합 테스트 2개: 일반·무결성 배치를 수거한 뒤 기억에 번역이 기록되고, 추출기 호출과 남은 추출 작업이 0건이다. 일반 쪽은 이어서 실시간 마무리를 돌려, 남은 1청크만 추출되는 것을 확인했다.
- 수정 전 코드에서 두 테스트가 실패하는 것(수거 때 추출 호출)을 확인했다.
- 전체 테스트: 505 passed, 7 skipped (프로젝트 가상환경, Python 3.10.11).
- 실제 Batch API와 실제 모델로는 확인하지 않았다.

## 미해결

- 추출 요청이 thinking level을 넘기지 않아 기본값 HIGH가 걸린다. 실시간 경로에서도 느리고 비싸다.
- 실시간 경로에서도 추출기는 번역과 다른 스케줄러를 쓰므로, 추출 요청과 번역 요청이 다른 키로 동시에 나갈 수 있다.
- 같은 로그의 RuntimeWarning(AsyncClient.aclose never awaited)은 google-genai 클라이언트가 가비지 컬렉션될 때 남는 정리 코루틴에서 나온 것으로 보이나, 어떤 클라이언트 객체였는지는 특정하지 못했다.
