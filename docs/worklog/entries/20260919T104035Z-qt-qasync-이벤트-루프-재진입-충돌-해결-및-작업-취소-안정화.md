## 배경

PySide6와 qasync를 결합하여 번역 및 용어집 추출 작업을 비동기 코루틴으로 구동하고, 작업 진행 중 사용자가 중지 버튼을 눌러 작업을 안전하게 중단할 수 있도록 지원한다.

## 문제

Python 3.12 환경에서 용어집 추출 중 "추출 중지" 버튼을 누르면 `RuntimeError: Cannot enter into task <Task cancelling ...> while another task <Task pending ...> is being executed`가 발생하며 크래시 또는 중단 불가 상태에 빠지는 현상이 발생했다.

## 결정과 근거

근본 원인은 `@asyncSlot` 비동기 슬롯 내부에서 취소 예외 처리 도중 동기 시그널(`completion_signal.emit()`)을 발생시키고, 슬롯에서 즉시 `QMessageBox` 모달 다이얼로그(`exec()`)를 호출한 점이다. 모달의 중첩 이벤트 루프가 구동되는 동안 취소 대기 중이던 하위 세그먼트 추출 태스크의 완료 콜백(`Task.task_wakeup`)이 디스패치되면서, 부모 태스크가 스택에 물려 있는 상태에서 하위 태스크로 진입하려다 Python 3.12의 재진입 방지 검사에 걸렸다. 또한 UI 중지 버튼이 외부 래퍼 태스크를 직접 강제 취소(`cancel()`)하여 서비스 계층의 정상적인 취소 이벤트 감지 및 부분 결과 파일 보존 처리를 방해했다.

버린 접근:
- `QMessageBox` 호출 전에 `asyncio.sleep(0)`을 두는 방식: 코루틴 컨텍스트를 벗어나지 못하므로 모달이 열리는 순간 여전히 동일한 태스크 재진입 위험이 남음.
- 팝업 다이얼로그를 일괄 제거하고 라벨에만 표시하는 방식: 사용자에게 작업 완료/중단 및 파일 저장 결과를 명확하게 알리는 UX를 해침.

채택한 결정:
1. `completion_signal.connect(self._on_completion, QtCore.Qt.QueuedConnection)`을 적용하여 완료/중단 팝업 다이얼로그 호출을 현재 코루틴이 완전히 종료된 후 다음 Qt 이벤트 루프 틱으로 지연 큐잉했다. 이를 통해 `current_task`가 비어있는 상태에서 모달 루프가 안전하게 열린다.
2. `_on_stop_clicked`에서 외부 태스크를 강제 `cancel()`하지 않고 `app_service.cancel_glossary_async()` 협력 취소만 트리거하도록 정정하여, 완료된 세그먼트까지의 부분 결과가 안전하게 병합 저장되고 경로가 UI에 표시되도록 개선했다.
3. 동일한 패턴을 공유하는 설정 탭의 번역 완료 시그널 및 취소 코루틴에도 `QueuedConnection`과 `CancelledError` 방어를 일관되게 적용했다.

## 검증

`test_glossary_segment_retry.py`, `test_settings_tab_qt_simple.py`, `test_gui_lifecycle_pytest.py`, `test_translation_cancellation.py` 등 관련 테스트 스위트 31개 항목 전체 통과를 확인했다.

## 미해결

미니PC Linux GUI 환경(X11/Chrome Remote Desktop)에서 실제 작업 취소 동작을 수행하여 팝업 다이얼로그 정상 출력 및 콘솔 traceback 부재를 사용자가 직접 확인해야 한다.
