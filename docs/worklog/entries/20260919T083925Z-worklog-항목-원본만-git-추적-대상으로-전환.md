## 배경

공통 기록 정책은 WORKLOG 항목 원본을 코드와 같은 커밋에 넣도록 한다. 이 저장소는 `.gitignore`가
`/docs` 전체를 제외하고 있어 항목을 커밋할 수 없었다. RPM 제어 리팩터 T1 커밋에서는 이 때문에
판단 근거를 커밋 메시지로 대신했다.

## 문제

`/docs`에는 항목 원본 외에 개인 프롬프트, 계획서, 임시 메모, 브레인스토밍 브리프, 생성물
`docs/WORKLOG.md`가 섞여 있다. 저장소가 공개 상태라 `/docs` 제외를 통째로 풀면 이 문서들이 모두
공개된다.

## 결정과 근거

- `/docs`를 `/docs/*`로 바꾸고 `docs/worklog/entries/`만 다시 포함했다. 부모 디렉터리를 통째로
  제외하면 하위 파일을 `!`로 되살릴 수 없으므로 `/docs/*` → `!/docs/worklog/` → `/docs/worklog/*` →
  `!/docs/worklog/entries/` 순서로 한 단계씩 열었다. 생성물 `docs/WORKLOG.md`와 나머지 개인 문서는
  계속 제외된다.
- 브리프(`docs/brainstorm/`)는 착수 전 예상이라 공개 기록으로 남길 대상이 아니라고 보고 제외를
  유지했다. 사용자가 추적을 원하면 같은 방식으로 한 줄을 더한다.
- 이미 있던 항목 4개(2026-09-01~03, Interactions API 마이그레이션과 QFluentWidgets UI 개편)는
  커밋하지 않았다. `main`과 로컬 브랜치 `interaction-api-migration`, `feature/pyside6-migration`
  어디에도 해당 코드(`interactions`, `qfluentwidgets` 참조)가 없어서다. 코드 없이 기록만 `main`에
  들어가면 병합되지 않은 작업이 사실처럼 남는다.

## 검증

- `git check-ignore`로 `docs/worklog/entries/*`는 추적, `docs/WORKLOG.md`·`docs/temp.md`·
  `docs/brainstorm/*`·계획서는 제외됨을 확인했다.
- `worklog.ps1 validate` 통과(기존 4개 항목 기준).

## 미해결

- 기존 항목 4개가 기록한 작업이 어디에 있는지 확인하지 못했다. 이제 폴더가 추적 대상이라
  `git add -A` 시 함께 들어갈 수 있으므로, 해당 작업의 저장소로 옮기거나 정리해야 한다.
- 이후 항목은 공개 저장소에 그대로 노출된다. 비밀정보나 공개하기 어려운 판단이 들어가지 않게
  작성 시점에 걸러야 한다.
