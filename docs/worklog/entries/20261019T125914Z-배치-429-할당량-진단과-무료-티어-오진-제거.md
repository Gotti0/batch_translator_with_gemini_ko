## 배경

2026-10-19 07:27:35 배치 제출 실패 로그에는 429 RESOURCE_EXHAUSTED와 도움말 링크만 있었다. 사용자가 RPM, RPD, TPM, 배치 대기열 토큰, 인라인 배치 제한 중 무엇이 번역을 중단시켰는지 식별할 수 있는 로그를 요청했다.

## 문제

2026-10-19 확인 시 배치 예외 래퍼는 quota 또는 billing이라는 일반 문구만 있어도 무료 티어 안내를 붙였다. 실제 서버 응답에는 티어와 초과한 할당량 식별자가 없었으므로 이 안내는 근거 없는 원인 단정이었다. SDK 원본 오류는 보존됐지만 할당량별 요약과 응답 헤더의 추적 정보는 기록하지 않았다.

## 결정과 근거

- QuotaFailure의 quotaMetric, quotaId, quotaValue, quotaDimensions와 ErrorInfo의 할당량 메타데이터를 추출한다. 식별자에서 RPM/RPD/TPM/TPD, 배치 대기열 토큰, 인라인 배치를 구분하며 원본 식별자를 함께 남긴다. 여러 위반은 모두 보존하고, 알 수 없는 식별자는 UNKNOWN으로 남긴다.
- 제출 방식과 할당량 종류는 별개다. 인라인 요청이라는 이유만으로 인라인 할당량 초과로 판정하지 않는다. 기간도 서버 식별자가 명시한 경우에만 기록한다.
- 배치 클라이언트의 429 처리에서 재시도 정보와 허용된 응답 헤더의 요청 ID를 기록한다. 제출 때는 모델, 인라인 여부, 요청 수와 기존 키 지문을 추가한다. 키 원문, 요청 본문, 표시용 파일명과 나머지 헤더는 새 진단 로그에 넣지 않는다.
- 무료 티어 안내는 서버 메시지가 free tier를 명시한 제출 오류에만 붙인다. 기존 예외 타입과 재시도·종료 정책은 유지하고 종료 오류 메시지에 할당량 요약을 덧붙인다.

## 검증

- 2026-10-19 프로젝트 가상환경에서 배치 클라이언트와 배치 서비스 테스트 38개 통과. 전체 test 디렉터리 테스트는 522 passed, 7 skipped, 종료 코드 0.
- SDK ClientError 합성 응답으로 여러 할당량 위반과 제한값, 기간, 모델, RetryInfo, 요청 ID가 함께 보존되는지 확인했다. 테스트용 식별자와 한도는 실제 프로젝트 측정값이 아니다.
- 당시 오류와 같은 도움말 링크만 있는 응답은 UNKNOWN으로 표시되고 무료 티어 안내는 나오지 않는다. 조회 중 ErrorInfo만 반환되는 경우와 비정상 details 형식에서도 원본 429 예외를 유지한다.
- 새 진단 로그에 요청 원문, API 키, 표시용 파일명, 비허용 응답 헤더가 포함되지 않는지 검사했다. git diff --check 통과.

## 미해결

- 서버가 할당량 식별자를 제공하지 않으면 로깅만으로 세부 원인을 확정할 수 없다. 프로젝트 할당량 사용 기록과의 대조가 필요하다.
- 실제 유료 API 호출이나 실행 중 앱 재시작은 하지 않았다. 수정된 로컬 소스를 새로 실행할 때 적용되며, 별도 배포 실행 파일은 다시 빌드해야 한다.
- 변경 범위는 Gemini 배치 클라이언트의 HTTP 429 처리다. 실시간 클라이언트의 기존 할당량 정책이나 비동기 작업 결과의 개별 항목 오류 처리는 변경하지 않았다.
