## 배경
사용자 피드백 분석 결과 최우선 대응(P1)이 필요한 두 가지 데이터 무결성 결함이 확인되었다:
1. EPUB 번역 후 전자책 뷰어(Calibre, Sigil, MoonReader 등)에서 챕터를 열 때 HTML 태그가 일반 텍스트로 노출되거나, CSS 셀렉터 미적용으로 삽화 이미지가 3000px 원본 해상도로 폭주하여 화면을 벗어나 잘리는 현상.
2. 표준 번역 시 Gemini 안전 필터(검열)에 걸려 재귀 분할이 한도에 도달했을 때 `[서브 청크 번역 실패]` 같은 에러 문구로 대체되어 독자가 원문 텍스트를 완전히 잃어버리는 현상.

## 문제
1. `utils/epub_processor.py`의 `reconstruct_chapter` 메서드가 챕터를 조립할 때 `<html><head>` 및 `</head><body>` 문자열을 단순 하드코딩으로 감싸고 있었다. 이로 인해:
   - 최상단 XML 선언(`<?xml ...?>`)과 DOCTYPE(`<!DOCTYPE html>`)이 누락되어 리더기 엄격 XML 파서가 파싱 실패 후 플레인 텍스트 모드로 폴백하여 태그를 그대로 노출함.
   - 루트 `xmlns="http://www.w3.org/1999/xhtml"` 네임스페이스와 `html`/`body` 태그 속성(`class="vrtl"`, `class="p-text"`, `xml:lang="ja"`)이 통째로 삭제되어 스타일시트 셀렉터가 매칭되지 않아 이미지 크기 제어(`max-width: 100%`)가 무력화됨.
   - 번역문 내 `<, >, &` 등 특수문자가 XML 엔티티로 처리되지 않아 XML 파서 문법 오류를 일으킴.
2. `domain/translation_service.py`의 `_translate_with_recursive_splitting_async`는 분할 한도 초과나 최소 크기 도달 시 에러 문자열을 반환하여 원문을 파괴하고 있었다. 이는 무결성 번역(실패 시 `{u.id: u.text}`) 및 EPUB 번역(실패 시 원본 파일 보존)의 원문 보존 정책과 정면으로 배치되는 불일치였다.

## 결정과 근거
1. **EPUB XHTML 규격 및 태그 속성 보존**:
   - `core/dtos.py`의 `EpubChapter` 모델에 `xml_declaration`, `doctype`, `html_attributes`, `body_attributes` 필드를 추가.
   - `EpubProcessor.process_chapter`에서 파싱 시 파일 시작 부분 정규식으로 XML 선언과 DOCTYPE을 추출하고, `soup.html.attrs`와 `soup.body.attrs`를 보존.
   - `EpubProcessor.reconstruct_chapter`에서 원본 선언부를 최상단에 복원하고, `xmlns="http://www.w3.org/1999/xhtml"`을 기본 보장하며 루트 및 본문 속성을 복원. 본문 번역 텍스트는 `html.escape(..., quote=False)`로 이스케이프하여 유효한 XML 트리를 형성하도록 수정.
2. **표준 번역 실패 대체 정책 통일 (원문 유지)**:
   - `TranslationService._translate_with_recursive_splitting_async`에서 최대 분할 시도 초과, 최소 청크 크기 도달, 분할 불가, 서브 청크 최종 번역 실패 및 예외 발생 시 에러 안내 문구 대신 원문 서브 청크(`sub_chunk` / `text_chunk`)를 그대로 반환하도록 변경.
   - 사용자가 번역 완료 후에도 원본 텍스트를 손실 없이 확인하고 수동 재번역할 수 있도록 파이프라인 전반의 원문 무결성을 확보함.

## 검증
1. **EPUB XHTML 단위 테스트 신설 (`test/test_utils/test_epub_xhtml_standards.py`, 5건 통과)**:
   - XML 선언, DOCTYPE, `xmlns`, `class="vrtl"`, `class="p-text"` 복원 후 `xml.etree.ElementTree.fromstring` 엄격 파싱 검증 통과.
   - EPUB 2 다중 라인 DOCTYPE 보존 검증.
   - 선언부가 누락된 비표준 HTML 입력 시 유효한 XHTML 선언 자동 보충 검증.
   - 특수문자(`<, >, &`) 이스케이프 및 XML 파서 디코딩 복원 검증.
   - 번역 맵 누락 시 제목(`title`) 태그 원문 보존 검증.
2. **표준 번역 원문 보존 테스트 신설 (`test/test_domain/test_standard_safety_fallback.py`, 4건 통과)**:
   - 콘텐츠 안전 검열 차단 발생 시 서브 청크가 재귀 분할되어 안전 문장은 번역되고 검열 문장은 원문 텍스트로 보존됨을 확인.
   - 최대 분할 횟수 초과, 최소 청크 도달, 예기치 않은 오류 시 원문 그대로 반환됨을 확인.
3. **전체 회귀 테스트**:
   - `pytest test -q` 실행 결과 전체 546 passed, 7 skipped로 회귀 결함 0건 달성.
