## 배경

GitHub 이슈 #69에서 무결성 텍스트와 EPUB이 동시 작업 수를 따르지 않는다고 보고했다. 표준 번역은 설정값을 읽었고 두 모드는 청크를 순차 처리했다.

## 문제

제보 코드의 챕터 내부 세마포어만 적용하면 청크가 하나뿐인 챕터끼리 겹쳐 실행할 수 없다. 실패한 워커가 슬롯을 먼저 돌려주는 구조에선 호출자가 정리하기 전에 후속 청크가 시작될 수 있었다.

## 결정과 근거

- 하나의 파일에 고정 개수 워커를 두고 다음 청크는 필요할 때만 가져온다. 치명적 오류나 취소를 받은 워커는 다른 워커가 다음 청크를 가져가기 전에 중단 상태를 기록한다.
- 무결성은 줄 ID와 청크 인덱스로 결과를 저장한다. 처리 순서와 원문 순서가 달라도 결과 조립과 진행률이 유지된다. 워커가 둘 이상이면 동시에 시작된 청크가 앞선 청크의 번역 기억을 받기 전에 프롬프트를 준비할 수 있다.
- EPUB은 완료 챕터의 캐시를 먼저 쓰고 최종 ZIP을 별도 파일에 원래 항목 순서로 작성한다. 취소 후 완료된 챕터를 재사용할 수 있고 기존 출력은 최종 파일이 준비될 때까지 보존된다.
- Gemini의 실제 API 동시 요청 한도는 기존 스케줄러가 관리한다.

## 검증

- 2026-11-24 로컬 Qt offscreen 환경에서 전체 테스트 594개 통과, 7개 건너뜀.
- 신규 회귀 테스트 11개에서 워커 1·2, 챕터 간 동시 실행, 치명적 오류 이후 후속 청크 차단, 취소 후 재개, 부분 결과 복원, 진행률, 원문·아카이브 순서 및 가로쓰기 정규화를 검증했다.
