## 배경

용어집 탭의 편집기에서 "저장 후 닫기"를 누르면 편집 결과가 용어집 탭의 읽기 전용 표시란에 들어가고 설정이 저장됐다. 사용자가 이 버튼의 로직 점검을 요청했다.

## 문제

설정에는 용어집의 경로만 있고 내용은 없다. 번역은 용어집 파일을 읽으므로 편집 결과는 번역에 반영되지 않았고, 재시작하면 사라졌다. 반영하려면 사용자가 "용어집 JSON으로 저장"으로 올바른 파일을 골라 따로 덮어써야 했다.

올바른 파일을 고르는 것도 자명하지 않았다. 번역 시작 시 AppService는 입력 파일 옆 <입력파일명><접미사>(기본 _simple_glossary.json)가 있으면 설정된 용어집 경로보다 그 파일을 먼저 쓴다. 설정 경로에만 저장했다면 그 파일이 있는 경우 같은 증상이 남았을 것이다.

## 결정과 근거

사용자 결정에 따라 입력 파일이 있으면 입력 파일 옆 용어집에 쓰고, 없으면 새로 만든다. 번역이 가장 먼저 찾는 파일이므로 여기에 쓰면 항상 반영된다. 탭의 용어집 경로도 그 파일로 맞춰 화면과 실제 사용 파일이 어긋나지 않게 했다.

트레이드오프: 사용자가 다른 곳의 용어집을 불러와 편집해도 원본 파일은 바뀌지 않고 입력 파일 옆에 사본이 생긴다. 원본에 쓰는 방식은 번역이 입력 파일 옆 파일을 우선하는 한 반영이 보장되지 않아 택하지 않았다.

입력 파일이 없을 때는 설정 경로에 쓰고, 그것도 없으면 저장 위치를 묻는다. 파일 쓰기에 실패해도 표시와 설정 저장은 진행하고 경고만 띄운다.

## 검증

- 테스트 4개 추가: 입력 파일 옆 용어집 생성과 경로 갱신, 설정 경로가 다른 파일이어도 입력 파일 옆 용어집을 덮어쓰고 설정 경로 파일은 그대로 둠, 입력 파일이 없으면 설정 경로에 씀, 둘 다 없으면 저장 위치를 물음. 네 개 모두 수정 전 코드에서 실패하고 수정 후 통과했다. 전체 스위트가 통과했다.
- 실제 창에서 버튼을 눌러 번역까지 돌리는 확인은 하지 않았다.

## 미해결

- 편집기 검증 문구는 도착 언어가 필요하다고 하지만 실제로는 검사하지 않는다. 번역 로더는 target_language가 없는 항목을 조용히 버린다.
- GlossaryService의 접미사 기본값은 _glossary.json이고 설정 기본값과 AppService는 _simple_glossary.json이다. 설정에 값이 있으면 문제가 없지만, 설정에서 빠지면 추출 결과와 편집 저장 파일이 갈라진다.
- "선택 삭제"는 여러 줄을 골라도 현재 줄 하나만 지운다.
